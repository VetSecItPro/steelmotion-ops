# /repo-bootstrap - the baseline, per stack

Detect the stack first. Apply only the missing pieces, matched to the language and package manager.

## The baseline, in order

1. **Test framework + one smoke test + a `test` script** - the machinery to run tests at all
2. **A CI workflow that gates merges** - runs lint/typecheck/test/build; a required check on `main`
3. **`.gitignore`** covering the stack's artefacts + `.env*` + the skill-report dirs
4. **CHANGELOG.md** if the repo ships a versioned artefact
5. **Pre-commit hooks** - format + lint on staged files
6. **Cost-optimisation config** - path filters, ignored-build-step, turbo/cache where warranted

## Documentation register (`--docs-register`, OPT-IN, deliberately not in the baseline)

Installs the `/docs-sync` machinery: `scripts/check-docs.py` (copy from
`~/.claude/skills/docs-sync/check-docs.py`, version-stamped) and a path-filtered
`.github/workflows/docs-check.yml`. It does **not** create the register.

**Why this is not applied by default, unlike everything else here.** Every other baseline element is
correct without judgement: a `.gitignore` for a stack is a `.gitignore` for that stack. A document
register is not - its anchors have to be curated by someone who read the citing lines, because a
document quotes what is WRONG (counter-examples, rename records, prohibitions) as often as what is
right. Auto-generating registers across repos would mass-produce exactly the failure `/docs-sync`
exists to prevent, at the one moment nobody is watching. So this flag installs the mechanism and
stops; run `/docs-sync --bootstrap` in the repo to build the register with a human in the loop.

Installing the gate without a register is safe: the checker exits 3 and the workflow fails loudly,
rather than passing silently on a repo it cannot check.

## Test framework, by stack

| Stack | Framework | Script | Smoke test |
|---|---|---|---|
| Next.js / TS | Vitest | `"test": "vitest run"` | one passing `*.test.ts` |
| Node (services) | Vitest + `test:integration` (testcontainers) | both scripts | one unit + one integration |
| Python | pytest | `pytest` | one `tests/test_smoke.py` |
| Go | `go test` | - | one `*_test.go` |
| Rust | `cargo test` | - | one `#[test]` |
| Bash / infra | bats | - | one `tests/*.bats` |

## Agent definitions (`.claude/agents/`)

Every repo gets at least the two role definitions below. **The tool list is the point.** A
dynamically spawned `general-purpose` agent carries `Tools: *` - full write access. A definition
can withhold `Edit` and `Write`, which turns a discipline rule into a structural one.

| File | Tools | Why it exists |
|---|---|---|
| `readonly-verifier.md` | `Read, Grep, Glob, Bash` | No write tools, so it **cannot make a failing check pass by editing the check.** Steel Principle 1 enforced by tool scope, not by instruction. Reports `PASS`/`FAIL`/`INCONCLUSIVE` with exit codes as evidence |
| `scoped-implementer.md` | `Read, Edit, Write, Grep, Glob, Bash` | Declared file scope, no git state changes, returns a full manifest of every file touched. Closes the unaccounted-edits gap below `gh-push-guard.py`, which only covers push and PR-create |

**Global agents already cover every repo.** `readonly-verifier` and `scoped-implementer` live in
`~/.claude/agents/` and are inherited everywhere, so **do not copy them into a repo by default** -
a duplicate drifts from the global one and adds nothing. Write a repo-local agent only for a
repo-SPECIFIC role: a verifier that knows this stack's exact commands, a checker that understands
this repo's deploy target. `--agents` is therefore opt-in, not part of the default sweep.

**Definitions load at session start.** A freshly written agent file is not callable in the session
that wrote it. Verification of this element is therefore deferred to the next session - say so in
the report rather than claiming it works.

## Living project docs (`--docs`)

Three files, seeded on day one, so the repo starts accumulating its own instructions instead of
re-explaining itself every session. Named self-referentially per the global style rule.

| File | What goes in it | What must never go in it |
|---|---|---|
| `CLAUDE.md` | Things **true next month**: build and test commands, architecture, conventions, constraints, directories not to touch. Generated by `/init`, then pruned | Current status, in-flight work, anything with a date |
| `<name>-state-backlog.md` | Things true **right now**: goal, done, in progress, blocked, decisions and their reasons, numbered backlog. A hand-off note to a Claude with no memory of the conversation | History. It is not a log |
| `<name>-lessons-learned.md` | One heading plus **two or three sentences** per entry: what went wrong (especially what the AI got wrong unprompted), the correction, the guard. Optional one-line `Transferable:` | Paragraphs. A four-paragraph entry does not get re-read, which defeats the file |

**The state doc is overwritten in place, never appended to.** A correction stacked *underneath*
stale content leaves both loading, and the reader cannot tell which is current. This is not
hypothetical: `~/.claude/CLAUDE.md` carried a known-wrong multi-tenant section for months because the
2026-08-15 correction was written above it instead of replacing it.

**The lessons file is always tracked; the state file is tracked only when the repo is its subject**
(global rule, 2026-09-01: decided by subject, not type). `CLAUDE.md` is committed.

**Seed each file with real content, never a placeholder.** An empty template with `TODO` headings is
worse than no file: it looks handled and reads as done. If there is nothing true to write in a
section yet, omit the section.

## CI gate

The workflow runs the real commands (detected from the manifest) and **is a required status check**.
Key properties, per the CI cost standard:

- **`concurrency` with `cancel-in-progress: false` on any lock-holding job** (deploy, helm, terraform,
  kubectl) - cancelling mid-lock strands the release. Pure-check jobs may cancel.
- **`timeout-minutes` on every job.**
- **`permissions:` minimal** - default token is over-scoped.
- **Actions pinned to SHA**, not a moving tag.
- **A gate job that always runs** (no `paths:` filter) so a required check always reports - a
  path-filtered required check deadlocks PRs that miss its paths. Per-package build/test jobs stay
  path-filtered and are NOT required.

Branch protection itself (making the check required, enforce_admins) is the operator's action - it is
plan-gated on some accounts. The skill configures the check and tells the operator to enable
protection.

## .gitignore

Stack artefacts (`node_modules/`, `.next/`, `dist/`, `__pycache__/`, `target/`), `.env*`, OS files,
and the skill-report directories (`.sec-ship-reports/`, `.perf-reports/`, etc. - all skill output is
gitignored per the global rule). Never ignore the lockfile.

## Cost-optimisation (per the CI/Vercel cost standard)

- **Path-filtered workflows** - CLI-only or docs-only changes must not trigger the web CI chain.
- **Vercel `ignoredBuildStep`** - a shell short-circuit that skips the build when the deployed package
  was not touched, on every monorepo `vercel.json`.
- **Merge queue** where the repo does >2 PRs/day.
- **turbo.json + remote cache** on monorepos, to share cache across CI and Vercel.

Apply the full stack to monorepos; the caching layer alone to single-package repos.

## Pre-commit hooks

Format + lint on staged files (husky + lint-staged for Node, pre-commit for Python, a git hook for
others). Fast - a hook that runs the full suite gets disabled by the first person in a hurry. Keep it
to format + lint; the CI gate runs the tests.
